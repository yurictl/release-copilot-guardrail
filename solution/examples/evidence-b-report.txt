[BLOCK]  liveness-dependency-aware: livenessProbe points at a dependency-aware path '/health' (identical to the readiness path)
          at: container[gateway].livenessProbe.httpGet.path
          why: Liveness answers 'is this process wedged'; readiness answers 'can this pod serve traffic right now'. Wiring liveness to a dependency-aware endpoint converts a downstream brownout into a fleet-wide restart storm: every pod fails liveness at once, every pod is killed, and the cold-start penalty is paid on all of them simultaneously while the dependency is still degraded.
     evidence: Evidence C: 'liveness should not depend on Redis or model backends'; Evidence D: 'one pod restarted after failing liveness during Redis brownout'
          fix: Point livenessProbe at /live and leave readiness on the dependency-aware path.

[BLOCK]  rollout-capacity: rollout can drop to 0 available pod(s); floor is 3
          at: spec.strategy.rollingUpdate
          why: replicas=2, maxUnavailable=2, maxSurge=0. Worst case during the rollout is 2 - 2 = 0 available pods before any new pod becomes ready, and with maxSurge=0 no replacement pod can even be created until an old one is torn down. With a documented 20-40s warm-up, that window is minutes, not seconds.
     evidence: Evidence D: 'rollout took 6m and briefly ran with 2 available pods', p95 180ms -> 950ms, 5xx 3.8%
          fix: Require spec.replicas - maxUnavailable >= 3. Prefer a surge-only rollout for this service: maxUnavailable: 0, maxSurge: 2.

          at: container[gateway].livenessProbe
          why: initialDelaySeconds=0 + periodSeconds=10 x failureThreshold=3 = 30s. A pod that takes the documented 40s to warm its routing tables is restarted before it ever becomes ready, producing a crash-loop that looks like an application bug. This is a pre-existing gap in the current manifest, not something this PR introduced.
     evidence: Evidence C: 'startup can take 20-40 seconds while model routing tables warm up'
          fix: Add a startupProbe (e.g. periodSeconds: 5, failureThreshold: 18) so liveness only starts counting once the process is up.
